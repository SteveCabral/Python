What the Program Does

This project asks the National Weather Service for a live forecast and prints the next six forecast periods in the terminal. Six periods normally represent three day/night pairs, such as daytime, nighttime, and the following day.

The program does not contain weather data itself. Instead, it sends an HTTP request to a web API, receives JSON data, selects the useful fields, and displays them.

The important idea An API is a program-to-program conversation. This script asks a remote service a question, receives structured data, and uses that data in Python.

The API Workflow

The National Weather Service API uses two related requests:

1. Locate the forecastThe /points request converts latitude and longitude into a forecast URL for that location.
2. Get the forecastThe forecast URL returns the actual periods, temperatures, wind, and descriptions.
3. Read the JSONPython follows keys such as properties and periods to reach the values.
4. Display the resultsA for loop prints the first six periods in a readable format.

The starting coordinates in this example are Washington, D.C.:

https://api.weather.gov/points/38.9072,-77.0369

Code Walkthrough

Import the library

import requests

import makes code from another module available. Here, the program imports the requests package so it can send web requests.

Define a reusable function

def get_weather():

A function is a named group of instructions. The function does not run when Python first reads its definition; it runs later when the program calls get_weather().

Prepare request headers

headers = {
    'User-Agent': 'MyWeatherApp/1.0 (contact@example.com)',
    'Accept': 'application/geo+json'
}

Headers are extra information sent with a request. The National Weather Service asks clients to identify themselves with a User-Agent. The Accept header says that the program expects GeoJSON, a JSON format commonly used by location-based APIs.

Use your own contact information Replace contact@example.com with a real email address when you turn this into your own application. It helps the API operator identify your program.

Make the points request

points_url = "https://api.weather.gov/points/38.9072,-77.0369"
response = requests.get(points_url, headers=headers, timeout=10)
response.raise_for_status()
data = response.json()

requests.get() sends an HTTP GET request. The URL contains the latitude and longitude. timeout=10 prevents the program from waiting forever if the service does not respond. raise_for_status() turns an unsuccessful HTTP response into an exception. Finally, json() converts the response body into Python dictionaries and lists.

Find the forecast URL

forecast_url = data['properties']['forecast']

The first response is metadata: information about where the actual forecast lives. Square brackets access dictionary values by key. This line moves through the properties dictionary and saves its forecast value.

Request and read the forecast

forecast_response = requests.get(forecast_url, headers=headers, timeout=10)
forecast_response.raise_for_status()
forecast_data = forecast_response.json()
periods = forecast_data['properties']['periods']

The second request uses the URL supplied by the API. Its response contains a list of forecast periods. A list is an ordered collection, so the program can select its first six items.

Loop over forecast periods

for period in periods[:6]:
    name = period['name']
    temperature = period['temperature']
    unit = period['temperatureUnit']
    detailed_forecast = period['detailedForecast']

    print(f"\n{name}: {temperature}°{unit}")
    print(f"   {detailed_forecast}")

periods[:6] is a slice: it means “items from the beginning up to, but not including, index 6.” Each period is a dictionary. The code reads four values and inserts them into formatted strings with an f-string.

Choose when the program starts

if __name__ == "__main__":
    get_weather()

This common Python pattern calls the function only when weather.py is run directly. It prevents the request from running automatically if another Python file imports get_weather later.

Understanding the JSON

A simplified version of the API response looks like this:

{
  "properties": {
    "forecast": "https://api.weather.gov/gridpoints/...",
    "periods": [
      {
        "name": "This Afternoon",
        "temperature": 85,
        "temperatureUnit": "F",
        "detailedForecast": "Mostly sunny..."
      }
    ]
  }
}
Python expression Meaning
data['properties'] Get the main metadata dictionary.
['forecast'] Get the URL for the detailed forecast.
forecast_data['properties']['periods'] Get the list of forecast periods.
period['temperature'] Get the temperature from one period.

Errors and Timeouts

try:
    # Requests and JSON parsing happen here.
except requests.exceptions.RequestException as error:
    print(f"Weather API request failed: {error}")
except ValueError as error:
    print(f"Weather API returned invalid JSON: {error}")

The try block contains operations that can fail. A network error, timeout, or unsuccessful HTTP status is handled by the first except block. Invalid JSON is handled by the ValueError block. Instead of a long traceback, the user receives a short explanation in the terminal.

Why the API URL matters https://weather.gov is a web page and returns HTML. The program must use https://api.weather.gov with a /points path so that response.json() receives structured API data.

Beginner Glossary

Term Meaning
API A set of rules that lets one program request data from another program.
HTTP GET A request used to retrieve information from a server.
URL The web address used to locate a resource.
JSON Text formatted as objects and arrays so programs can exchange structured data.
Dictionary A Python collection of key/value pairs, written with curly braces.
List An ordered Python collection, written with square brackets.
Exception An event that interrupts normal execution because something went wrong.
Timeout A limit on how long the program waits for a response.
