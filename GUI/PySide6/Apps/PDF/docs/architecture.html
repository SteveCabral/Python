Overview

The application follows the same Model / View / Configuration separation pattern used by the other PySide6 apps in this repository. Each layer has a distinct responsibility and may be understood or modified without touching the other layers.

├── requirements.txt           ← PySide6 + pypdf

Layer responsibilities

config/settings.py

Constants only — no logic, no imports beyond the standard library.

Symbol Purpose
APP_NAME, APP_VERSION Title bar text
POINTS_PER_INCH PDF unit conversion (1 in = 72 pt)
LETTER_SIZE_IN, LEGAL_SIZE_IN Reference page sizes in inches (short, long)
SIZE_TOLERANCE_PT Allowed rounding error, in points, when matching a page size
LABEL_LETTER, LABEL_LEGAL Row/label text shared between the model and the view
CONTROL_FONT_FAMILIES, CONTROL_FONT_SIZE_PX Application-wide UI font (default Segoe UI, 13 px — the same as the Visual Studio Code menu), applied in main.py
LEGAL_TEXT_COLOR Text color (default bright red #FF0000) for the Page Range, Size, and Total cells of Legal rows

model/pdf_page_analyzer.py

Pure business logic; contains no PySide6 imports and is independently testable.

PdfPageReport

An immutable dataclass holding the result of analysing one PDF:

@dataclass(frozen=True)
class PdfPageReport:
    file_name: str
    file_path: Path
    page_count: int
    letter_pages: list[int]   # 1-based page numbers
    legal_pages: list[int]    # 1-based page numbers
    other_pages: list[int]    # 1-based page numbers that are neither size

PdfPageAnalyzer

A stateless class with three static methods:

Method Description
analyze(pdf_path) Opens the PDF with pypdf, reads each page's mediabox, and classifies it by comparing its short/long edges (in points) against the Letter and Legal reference sizes within a tolerance
format_page_range(pages) Collapses a sorted list of 1-based page numbers into a compact range string, e.g. [1, 2, 4] → "1-2, 4"
split_page_ranges(pages) Splits a sorted list of page numbers into separate range strings, e.g. [1, 4, 5] → ["1", "4-5"]; used by the By Page Range view and by format_page_range

Orientation independence: pages are compared using their sorted (short edge, long edge) pair rather than raw width/height, so a landscape-rotated Letter page (792 × 612 pt) still matches the same reference as a portrait Letter page (612 × 792 pt).

view/main_window.py

Owns the entire UI layout. Key components:

Widget Role
Open PDF button Opens a native file dialog filtered to *.pdf, starting at the previously selected PDF's directory
_name_value / _path_value Labels showing the selected file's name and full path
_by_size_btn / _by_page_btn Checkable, mutually exclusive By Page Size and By Page Range buttons (QButtonGroup) that choose which table is visible
QStackedWidget Holds the two tables and shows only one at a time, switched by the view buttons
_grid (QTableWidget) By Page Size table: one row per size (Letter, Legal, each other size) with a comma-separated page-range string, size label, total count, and Copy button
_page_grid (QTableWidget) By Page Range table: one row per individual page range, sorted by starting page, with a narrower fixed-width Page Range column
_add_row() Shared row builder for both tables: adds the page-range, size, and total cells (Legal rows use LEGAL_TEXT_COLOR) and a Copy button that copies that row's page range to the system clipboard via QApplication.clipboard(); the button is disabled when the range is empty
_populate_page_grid() Builds the By Page Range rows from the size groups using split_page_ranges
statusBar() Running single-line summary of the current scan / last copy action, separated from the table by a top border

main.py

Minimal entry point: creates QApplication, instantiates MainWindow, calls show() and exec().
