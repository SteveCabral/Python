What Collection Types Are

A collection is a data structure that holds a group of items. Python’s built-in collection types fall into three families:

  • Sequences — ordered items accessed by index (list, tuple, range, str)
  • Mappings — key-to-value lookup (dict)
  • Sets — unique, unordered items (set, frozenset)

The four types you will use most often are list, tuple, dict, and set. Python also provides frozenset, range, text and binary sequences, and extra types in the collections module.

Shared behavior All of these support len(), in / not in, and iteration with for. That is what makes them collections.

Quick Comparison

Type Family Ordered? Mutable? Duplicates? Typical use

list

A list is an ordered, mutable sequence. Use it when you need a collection that can grow, shrink, or change in place.

Code

numbers = [4, 7, 9, 3]
names = ["Ada", "Grace", "Linus"]
empty = []

numbers.append(8)
numbers.insert(0, 1)
first = numbers[0]
last = numbers[-1]
slice_of = numbers[1:4]
names[1] = "Alan"
removed = numbers.pop()

print(numbers)
print(first, last, slice_of)
print(names)
print(removed)
print(len(names), "Ada" in names)

Output

[1, 4, 7, 9, 3]
1 8 [4, 7, 9]
['Ada', 'Alan', 'Linus']
8
3 True

Common operations:

  • append, insert, extend — add items
  • pop, remove, del — remove items
  • sort, reverse — reorder in place
  • indexing and slicing — read or replace a range

tuple

A tuple is an ordered, immutable sequence. Use it for fixed groups of values, return values, or as a dict key when the contents are hashable.

Code

point = (10, 20)
rgb = (255, 128, 0)
single = (7,)          # comma is required for a 1-item tuple
also_a_tuple = 1, 2, 3 # parentheses are optional
empty = ()

x, y = point           # unpacking
print(point[0], point[-1])
print(single, also_a_tuple)
print(x, y)
print(len(rgb), 128 in rgb)

Output

10 20
(7,) (1, 2, 3)
10 20
3 True
One-item tuples need a comma (7) is just the integer 7. (7,) is a tuple containing 7.

Tuples cannot be changed after creation. Methods like append do not exist. You can still concatenate to make a new tuple: 

point = (10, 20)
moved = point + (5,)
print(moved)   # (10, 20, 5)

dict

A dict maps unique keys to values. Lookup by key is the usual reason to use one. Since Python 3.7, dicts keep insertion order.

Code

person = {"name": "Ada", "year": 1815}
person["field"] = "computing"
person["year"] = 1815

print(person["name"])
print(person.get("city", "unknown"))
print(list(person.keys()))
print(list(person.values()))

for key, value in person.items():
    print(key, "=", value)

del person["field"]
print("field" in person)

Output

Ada
unknown
['name', 'year', 'field']
['Ada', 1815, 'computing']
name = Ada
year = 1815
field = computing
False
Keys must be hashable Numbers, strings, and tuples of hashable values can be keys. Lists, dicts, and sets cannot.

Empty {} is a dict, not a set

empty_dict = {}
empty_set = set()
print(type(empty_dict), type(empty_set))
<class 'dict'> <class 'set'>

set

A set is an unordered collection of unique, hashable items. Use it for membership tests, removing duplicates, and set math (union, intersection, difference).

Code

tags = {"python", "sql", "git", "python"}
primes = {2, 3, 5, 7}

tags.add("linux")
tags.discard("sql")

print(tags)
print("git" in tags)
print({1, 2, 2, 3, 3, 3})   # duplicates dropped

a = {1, 2, 3, 4}
b = {3, 4, 5}
print(a | b)   # union
print(a & b)   # intersection
print(a - b)   # difference
print(a ^ b)   # symmetric difference

Output

{'linux', 'python', 'git'}
True
{1, 2, 3}
{1, 2, 3, 4, 5}
{3, 4}
{1, 2}
{1, 2, 5}
Sets are unordered Do not rely on print order. Use a set when identity and uniqueness matter, not position. Items must be hashable, so a set cannot contain a list.

frozenset

A frozenset is an immutable set. Once created, you cannot add or remove items. That makes it usable as a dict key or as a member of another set.

Code

permissions = frozenset({"read", "write"})
print(permissions)
print("read" in permissions)

# frozenset can be a dict key; set cannot
roles = {
    frozenset({"read"}): "viewer",
    frozenset({"read", "write"}): "editor",
}
print(roles[frozenset({"read", "write"})])

Output

frozenset({'write', 'read'})
True
editor

Union and intersection still work; they return a new frozenset instead of changing the original.

range

A range is an immutable sequence of integers. It does not store every number; it stores start, stop, and step, so large ranges stay cheap. It is the usual way to loop a fixed number of times.

Code

print(list(range(5)))
print(list(range(2, 8)))
print(list(range(0, 10, 2)))
print(list(range(5, 0, -1)))

for i in range(3):
    print("tick", i)

r = range(10, 20)
print(len(r), r[0], r[-1], 15 in r)

Output

[0, 1, 2, 3, 4]
[2, 3, 4, 5, 6, 7]
[0, 2, 4, 6, 8]
[5, 4, 3, 2, 1]
tick 0
tick 1
tick 2
10 10 19 True
Stop is exclusive range(5) is 0, 1, 2, 3, 4 — it does not include 5.

str (text sequence)

A string is an immutable sequence of Unicode characters. It is a collection of characters, so indexing, slicing, in, and len() work the same way they do for lists and tuples.

Code

text = "Python"
print(text[0], text[-1], text[0:3])
print("th" in text)
print(list(text))
print("-".join(["A", "B", "C"]))
print(text.upper(), text.replace("Py", "Jy"))

Output

P n Pyt
True
['P', 'y', 't', 'h', 'o', 'n']
A-B-C
PYTHON Jython

Because strings are immutable, methods such as upper() and replace() return a new string. They do not change the original.

bytes and bytearray

These are sequences of integers in the range 0–255. Use them for binary data (files, network payloads), not ordinary text.

  • bytes — immutable
  • bytearray — mutable version of the same idea

Code

raw = b"ABC"
mutable = bytearray(b"ABC")
mutable[0] = 90   # 90 is 'Z'

print(raw, list(raw))
print(mutable)
print(raw.decode("ascii"))

Output

b'ABC' [65, 66, 67]
bytearray(b'ZBC')
ABC

deque

collections.deque (double-ended queue) is a mutable sequence optimized for adding and removing items at both ends. A list is fast at the right end, but slow at the left end.

Code

from collections import deque

q = deque(["b", "c"])
q.append("d")       # right
q.appendleft("a")   # left
print(q)

print(q.pop())       # right
print(q.popleft())   # left
print(q)

Output

deque(['a', 'b', 'c', 'd'])
d
a
deque(['b', 'c'])

Use a deque for queues, sliding windows, and any “work from both ends” pattern.

namedtuple

A named tuple is an immutable tuple whose fields have names. You still get index access, plus point.x style attributes.

Code

from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
p = Point(10, 20)

print(p)
print(p.x, p.y)
print(p[0], p[1])
print(p._asdict())

Output

Point(x=10, y=20)
10 20
10 20
{'x': 10, 'y': 20}

typing.NamedTuple is the typed variant of the same idea. Both remain tuples underneath: immutable, unpackable, usable as dict keys.

defaultdict

A defaultdict is a dict that creates a default value when you first access a missing key, instead of raising KeyError.

Code

from collections import defaultdict

groups = defaultdict(list)
pairs = [("fruit", "apple"), ("color", "red"), ("fruit", "pear")]

for kind, item in pairs:
    groups[kind].append(item)

print(dict(groups))
print(groups["missing"])   # creates [] automatically

Output

{'fruit': ['apple', 'pear'], 'color': ['red']}
[]

Common factories: list, set, int (starts at 0, useful for counting).

Counter

A Counter is a dict specialized for counting hashable items.

Code

from collections import Counter

counts = Counter("banana")
print(counts)
print(counts.most_common(2))
print(counts["a"], counts["z"])   # missing keys are 0, not KeyError

counts.update("apple")
print(counts)

Output

Counter({'a': 3, 'n': 2, 'b': 1})
[('a', 3), ('n', 2)]
3 0
Counter({'a': 4, 'n': 2, 'p': 2, 'b': 1, 'l': 1, 'e': 1})

OrderedDict

Before Python 3.7, a regular dict did not guarantee order. OrderedDict existed to keep insertion order and to support extra methods such as move_to_end.

For new code, a plain dict is usually enough. Reach for OrderedDict when you need those extra reordering methods, or when order equality should matter (OrderedDict compares both keys/values and order; a regular dict compares only keys/values).

Code

from collections import OrderedDict

od = OrderedDict([("a", 1), ("b", 2), ("c", 3)])
od.move_to_end("a")
print(list(od.items()))

print({"a": 1, "b": 2} == {"b": 2, "a": 1})
print(OrderedDict(a=1, b=2) == OrderedDict(b=2, a=1))

Output

[('b', 2), ('c', 3), ('a', 1)]
True
False

ChainMap

A ChainMap groups several dicts into one lookup view. Search starts at the first mapping and continues until the key is found. Writes go to the first mapping only.

Code

from collections import ChainMap

defaults = {"color": "blue", "size": "M"}
user = {"size": "L"}
settings = ChainMap(user, defaults)

print(settings["color"])   # from defaults
print(settings["size"])    # from user (first match wins)
settings["color"] = "red"  # writes into user
print(user)
print(defaults)

Output

blue
L
{'size': 'L', 'color': 'red'}
{'color': 'blue', 'size': 'M'}

Useful for layered config: command-line overrides, then env, then defaults.

How to Choose

If you need… Start with
A sequence you will change list
A fixed record or dict key tuple or namedtuple
Lookup by name / identifier dict
Uniqueness or set math set
An immutable set (as a key) frozenset
A numeric loop or slice of integers range
Text str
Binary data bytes / bytearray
Fast add/remove at both ends deque
Grouping into lists without setdefault defaultdict(list)
Tallies / frequencies Counter
Layered lookups across several dicts ChainMap

Summary

Collection types hold groups of items. Pick the family first (sequence, mapping, or set), then mutability.

Family Built-in types Main extra types
Sequence list, tuple, range, str, bytes deque, namedtuple
Mapping dict defaultdict, Counter, OrderedDict, ChainMap
Set set, frozenset —

Notable Observations

  • list, tuple, dict, and set are the everyday four. Learn those first. The others are specialized versions of the same three families.
  • Mutability is the usual list-vs-tuple and set-vs-frozenset split. Immutable collections can be dict keys (if their contents are hashable).
  • {} is an empty dict, not an empty set. Write set() for an empty set and frozenset() for an empty frozenset.
  • Import extras from collections. deque, namedtuple, defaultdict, Counter, OrderedDict, and ChainMap are not built-in names; they live in the standard library.
